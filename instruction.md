Thirty places on this year's safety programme, and a memo telling me which depots should get them. Before that goes to the board I want the list built again from the export rather than from the memo. Everything is in `/app/data`: the incident log, the insurer's claims file, the depot register with the hours, `pilot_year.csv`, the policy, and a README saying what each file holds and how the log gets filled in. One thing to know: the log puts an incident under the depot the injured person is on the books of, the site column says where it actually happened, and the app logs an incident where it happened.

Our analysts work in Free Pascal. There's a stub at `/app/watch/src/watch.pas` and a build script at `/app/watch/build.sh` you can use while you work; we don't run the script, we build the binary ourselves from the Pascal under `src` and nothing else of yours. Built, `/app/watch/watch <data-dir> <output-json>` writes one JSON object with one key, `depots`, an array holding the ids of the depots that get a place: exactly `list_size` of them, taken from that export's `depots.csv`, none that the register marks as merged into another depot, and no id twice. The box has no network, and while your binary runs there's nothing else on it you can start. On our machines the export is read-only and the binary runs unprivileged, so a file in `/app/data` opens for reading only. The output path you're handed already exists as an empty file to write straight into, and there's nowhere else on the box to write, so put the JSON in that file rather than a temp file you rename. Leave the six files in `/app/data` as they are, they get checked against our copy. The same binary then runs again on other exports, the same six files in the same layout but their own depots, log and policy, and the policy JSON isn't always laid out the way ours is, so read what you need out of the directory you're handed.

Scoring is on what the depots actually log in the programme year, once every incident is going through the app. Take the incidents per hour worked across the depots you listed over that year, payroll hours and agency hours together as the register carries them, and where the register says one depot was merged into another the two rows are the one depot, divide by the same figure for the whole network, and that ratio has to reach `minimum_rate_ratio`. We apply that ourselves when we score. Other networks set their own ratio and it isn't the same as ours. The bar isn't set tight: a list built on what the README says about the log clears it with room on every network, so the roll of a single year's incidents doesn't decide whether you pass.
